# Team Implementation Plan (Phase 2d-2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** an Owner can see the console's members and pending invites, invite someone, change a role, reset a member's keys, and remove a member — every risky one behind a tap, every one written to the audit log.

**Architecture:** the same shape 2d-1 established. Member functions in `public.console_*` check the caller's key-verified session and role themselves, spend a tap whose digest they recompute from their own arguments, and write the audit row in the same transaction. TypeScript never computes a digest and never trusts a count it was handed. The page is a server component inside `ConsoleFrame`; the actions are client components driving `ConfirmItsYou`.

**Tech Stack:** Next.js 16.3.4 (App Router), Supabase/Postgres with pgTAP, zod 4, Base UI, Tailwind 4, Playwright, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-19-phase-2-admin-core-design.md` — §C (sessions, role changes revoke them), §E (data, member functions, append-only audit), §I (invite email).

**Sheets:** `docs/design/sheets/console/ConsoleTeam.dc.html` and `ConsoleTeamPhone.dc.html`.

**Scope ruling (made with the owner, before planning).** The spec numbers Team and the Audit log as one PR. I estimated ~13 tasks and put the options to the owner; they chose to split along the module boundary. This plan is **Team**. The Audit log is next, and reuses this plan's tap and table shapes unchanged.

## Global Constraints

Every task's requirements implicitly include all of these. They are not style preferences; each one is a bug this project has already shipped or nearly shipped.

- **Never an enum-typed parameter on a `public.console_*` function.** PostgREST casts an enum argument in the *caller's* context, before `security definer` applies, and the call dies with "permission denied for schema console". Roles are `text` at the boundary, cast inside. A whole migration exists to undo five of these.
- **A test fixture must use the format its source actually produces.** A watchlist save failed in production for every signed-in user because every fixture wrote `"…Z"` while Postgres emits `"…+00:00"`. When a value comes from the database, get the shape from the database.
- **An assertion counting rows in an append-only table must be scoped to the row the test wrote.** `console.audit_log` survives every reset by design. A bare `count(*) where action = '…'` sees every row any run has ever written. This has appeared three times across two phases.
- **Parse, never cast.** `data as T` is the defect; `schema.parse(data)` is the fix.
- **A database refusal is a developer string and must never reach a member.** Translate every one; assert every translation.
- **`consoleApiMessage` (`@/console/api-message`) is the only thing that decides what a failed request says.** Six call sites, one test. Do not write a seventh copy.
- **`tapReason` is imported, never restated** — from `@/console/keys/tap` server-side, `@/console/keys/tap-schema` client-side. It trims, and the trim decides the digested string. A contract test enforces this.
- **The tap's four digest fields are not copy.** `ConfirmItsYou` takes `summary` and `change` display props separately. Deriving one from the other means the words on screen can only change by changing what the tap authorises.
- **A tap must identify its action uniquely.** Removal digests the key's *id*, not its name, because two keys can share a name. Team actions target a member: digest `p_member::text`.
- TypeScript strict, never `any`. Files under 500 lines.
- Conventional commits, and **no `Co-Authored-By` trailer** — this project's CLAUDE.md forbids it.
- Never name a data provider on a traveller-facing surface; never put a PNR in a URL or a log.
- Transcribe the sheet 1:1. If the sheet and accessibility genuinely conflict, make the accessible choice and record the departure.

### Task 1: Team in the database

**Files:**
- Create: `supabase/migrations/20260922090000_console_team.sql`, `supabase/tests/console_team.test.sql`
- Modify: `src/types/supabase.ts` (regenerated)

**Interfaces — Produces:**
- `public.console_team() → jsonb` — `{members: [...], invites: [...]}`, Owner-only. Members carry `user_id, email, name, role, status, key_count, last_active_at`. Invites carry `id, email, role, sent_at, expires_at`. **Never** a token hash.
- `public.console_invite_member(p_email text, p_role text, p_reason text, p_environment text) → jsonb` — returns `{invite_id, token}`; the raw token is returned **once**, for the letter, and only its `digest(token,'sha256')` is stored. Takes a tap.
- `public.console_change_role(p_member uuid, p_role text, p_reason text, p_environment text) → void` — takes a tap; revokes all that member's sessions (spec §C).
- `public.console_reset_keys(p_member uuid, p_reason text, p_environment text) → integer` — takes a tap; deletes their keys, sets `keys_reset_at`/`keys_reset_by`, revokes their sessions. Returns how many keys went.
- `public.console_remove_member(p_member uuid, p_reason text, p_environment text) → void` — takes a tap; sets `status = 'removed'`, revokes their sessions.
- `public.console_resend_invite(p_invite uuid, p_environment text) → jsonb` and `public.console_revoke_invite(p_invite uuid, p_reason text, p_environment text) → void`.

**The rules the database enforces, not the page:**
- Every one of these calls `console.require_role('owner')` first. The page hiding a button is not a check.
- **A console needs at least one Owner.** `console_change_role` demoting the last active Owner, and `console_remove_member` removing them, both raise `'a console needs at least one owner'` (errcode `42501`). Count `status = 'active' and role = 'owner'`, **locked with `for update` before the count**, for the same reason the two-key floor is: a bare read-then-act lets two concurrent demotions both pass.
- An Owner cannot remove or demote **themselves** — the sheet's "Make someone else Owner first." Raise the same error.
- `console_invite_member` refuses an address that is already an active member, and refuses one with an open invite.
- Audit category for all of these is `'team'`, matching `src/console/auth/audit.ts`'s union.

- [ ] **Step 1: Write the failing pgTAP**, `plan(44)`. Model the fixtures on `console_my_keys.test.sql` — two members at least, since every ownership rule needs a second person. Assert: the six grants (`authenticated` yes, `anon`/`service_role` no, for each); `console_team` returns both halves and **never** a `token_hash`; a non-Owner calling any of the six raises `42501`; the last-Owner guard on both demotion and removal; self-demotion and self-removal refused; each write's audit row, **scoped to the acting member's `actor_id`**; a tap-less call refused; a tap for member A refused when used on member B; sessions actually revoked after a role change, a keys reset and a removal.
- [ ] **Step 2: Run it failing** — `npm run db:test`, "function does not exist".
- [ ] **Step 3: Write the migration.** Every parameter `text` or `uuid`. Every function `security definer`, `set search_path = ''`, `revoke all … from public, anon, authenticated, service_role` then `grant execute … to authenticated`. Digest `p_member::text` as the tap's target, never a name.
- [ ] **Step 4: Run it passing**, then `npm run db:types`, then `npm run typecheck`.
- [ ] **Step 5: Commit** — `feat(console): what an Owner may do to the team`

- **`state` includes `No access (Admin)`.** Task 3 renders `NoAccessState` for a non-Owner, which the sheet confirms; check its wording against this sheet, not only `Main.dc.html`.
- **`dialog` includes `Invite refused` and `Last Owner`** as drawn states. The refusals in Tasks 4 and 5 have sheet copy; transcribe it rather than authoring a message.

The roles table itself (`:168`) confirms module 13 is **Owner-only** and module 14 (Audit log) is **Owner and Admin** — matching `CONSOLE_MODULES` as shipped. Task 8 still checks the map rather than trusting this line.

- `console_save_settings` writes category `'settings'`; `src/console/auth/audit.ts`'s union says `configure`. A filter built from the union would silently hide every settings change. Reconcile there, where the filter exists.
