# Phase 0 · Part E: Enforced security headers implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the Content Security Policy blocks rather than only reports. Production upgrades insecure requests and reports violations to Sentry. A browser test visits every route in both themes and fails on any violation.

**Architecture:**

- `next.config.ts` sends `Content-Security-Policy` in place of `Content-Security-Policy-Report-Only`.
- Outside development it adds `upgrade-insecure-requests`. It isn't added in dev, where it would push `http://localhost` to https.
- In production only, it adds a `report-uri` to Sentry's security endpoint, derived from the public DSN. Previews aren't included, so the Vercel toolbar there doesn't fill Sentry.
- `tests/e2e/csp.spec.ts` collects `securitypolicyviolation` events.
- `E2E_BASE_URL` lets the same suite run against a deployed site. Then no local server starts.

**Spec:** `docs/superpowers/specs/2026-09-18-phase-0-foundations-design.md`, part E.

## Global Constraints

- Scripts stay `'self' 'unsafe-inline'`: Next 16 per-request nonces would force dynamic rendering. The admin host gets nonces in Phase 2.
- `connect-src` stays `'self'` plus Supabase. Sentry already travels through `/monitoring`.
- The report endpoint is `https://<host>/api/<project>/security/?sentry_key=<public key>`. The public key is public by design, and no secret is added.
- TDD, conventional commits with **no `Co-Authored-By`**, files under 500 lines.

### Task 1: Enforce the policy (unit)

- [ ] Failing tests in `tests/unit/next-config.test.ts`, loading the config after stubbing env:
  - the response carries `Content-Security-Policy` and no `-Report-Only`
  - production (`NODE_ENV=production`) adds `upgrade-insecure-requests`
  - `VERCEL_ENV=production` with a DSN adds `report-uri https://o1.ingest.de.sentry.io/api/2/security/?sentry_key=abc`
  - a preview, or no DSN, adds no `report-uri`
- [ ] Implement in `next.config.ts`, run the tests, commit: `feat(security): enforce the content security policy, reporting to Sentry in production`.

### Task 2: A browser test for violations, runnable against any deployment

- [ ] `tests/e2e/csp.spec.ts`: the axe route list, in both themes. An init script records every `securitypolicyviolation` (directive and blocked URI) on `window`. After `gotoReady`, the list must be empty.
- [ ] `playwright.config.ts`: `baseURL = process.env.E2E_BASE_URL ?? local`, and `webServer` only when `E2E_BASE_URL` is unset.
- [ ] Run locally (dev CSP), then `npm run check`. Commit: `test(security): fail on any CSP violation across every route and theme`.
